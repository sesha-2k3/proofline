# Decisions

- B1: Routers are registered through a `ROUTERS` list in `app/main.py`; it starts empty and later steps append to it.
- B1: The SPA fallback is a catch-all GET route registered after `/api` and `/samples`; it returns 404 for `/api/*` and `/samples/*`.
- B3: `rules_version()` returns `meta.last_reviewed` from rules/masshealth.yaml; the loader also rejects any non-null source not in `SOURCES`.
- B4: Mock records use the sample file name as `docId`; POST /documents replaces it with the request `doc_id`. Multipart form fields are named `file`, `doc_id`, `doc_type_hint` (snake_case, as in BUILD_PLAN).
- B4: Mock pipeline trace: all six stages "ok" for recognized files; for unknown files ingest/render "ok" and the rest "skipped", extractor "none", classificationConfidence "low".
- B4: Mock thresholds in Jorge data (shortfalls, "80"/"$580" in messages) are computed from rules accessors, not literals. Spanish summaries are in `SUMMARIES` in app/mocks/jorge.py.
- B4: POST /packet and /timeline return `application/pdf` with Content-Disposition attachment; no JSON response model.
- B5: Ledger collapses duplicate records (same doc_type, issuer case-insensitive, period start/end) before evaluating; it keeps a countable copy first, then the smallest id. Dropped duplicates appear in neither id list.
- B5: Volunteer records count only when org_type is in `allowed_volunteer_org_types()` and non_partisan is true (rule volunteer_org_requirement); ineligible ones are neither counted nor excluded (validation flags them in B10).
- B5: Income uses doc_type: gig_earnings → gig gross/net; paystub/employer_statement → employee gross; volunteer/school activities give no income. Gig net per month = max(0, gross share − expenses share), with gross and expenses split separately.
- B5: Proportional split rounds half up in integer arithmetic. A record counts in every window month its period overlaps. best_month is None only when there are no months to evaluate.
- B6: ground_truth.json is `{ "files": { <sample name>: { docType, records: [EvidenceRecord camelCase], notice: NoticeInfo | null } } }`; long lines shrink the font to stay on one line; PDFs are built with reportlab invariant=1 so reruns produce the same bytes.
- B7: Ingest accepts by extension (.pdf/.png/.jpg/.jpeg); MIME must match unless empty or application/octet-stream; files that won't open are UNSUPPORTED_FILE (HTTP 415). Keyword ties → no match (falls to LLM or "unknown"). Classification confidence: hint/keywords "high", LLM "low"; the LLM classifier is an injected client (B8 `LlmClient`) and returns None in demo mode. Images always render to PNG; PDF page images only when requested.
- B8: Raw extraction models (`RawField`/`RawRecord`/`RawNotice`/`RawExtraction`, snake_case keys matching EvidenceRecord) live in `pipeline/extract/models.py`; the stage entry `extract()` (template → LLM → none with warning "Enter the values manually.") is in `pipeline/extract/__init__.py`. Values stay raw ("$320.00", "04/01/2027"); volunteer month lines ("May 2027 hours") give ISO period dates. The "[handwritten" mark lowers only the value read from that line (hours), not the period taken from the printed month label, to match ground_truth.json. LLM transport errors count as a failed attempt and give up with no records.
- F1: Frontend pins TypeScript ~5.9 (Vite template default is 6.x) because openapi-typescript 7 requires a TypeScript 5 peer.
- B9: Grounding searches the field's own page line by line (whitespace-normalized; numbers/dates must not sit inside a longer number) and tries the extractor's evidence line first; evidence becomes the matching page line. Volunteer period dates on a month's first/last day also ground on the "<Month> <YYYY>" label. Null values are "not_checked" with confidence low; unparseable raw values normalize to null + low; LLM money given as a bare number is read as dollars (as printed).
- B9: Flag `field` uses the camelCase wire name (e.g. "grossCents"). Reversed periods add one DATE_OUT_OF_RANGE on periodEnd and lower both period dates. Date range 2025-01-01..2028-12-31 and the 2% arithmetic tolerance are constants in verify.py (BUILD_PLAN Appendix; not eligibility thresholds). Notices carry no flags; failed checks only lower confidence and set the verify stage to "warning".
- B9: Trace statuses: unknown type → classify "warning", extract "skipped"; no extractor for a known type → extract "warning"; nothing extracted → normalize/verify "skipped"; any ungrounded field or flag → verify "warning". Unknown documents get both "Could not recognize this document. Choose its type." and "Enter the values manually.". The LLM client is a FastAPI dependency (`get_llm_client`) so tests can inject a fake.
- B10: Validation flags (DUPLICATE, STALE_DOCUMENT, VOLUNTEER_ORG_INELIGIBLE, NAME_MISMATCH, LOW_CONFIDENCE_UNCONFIRMED) are recomputed on every call; verify flags are kept. POST /evaluate re-runs validation first so the best-month "flagged records" tie-break never uses stale flags. Flags do not change countability (ledger decision 1 only).
- B10: DUPLICATE flags only the copies the ledger drops (it keeps a countable one, then the smallest id). STALE_DOCUMENT applies to paystub and employer_statement (the rule's wording); exactly paystub_recency_days old is not stale. NAME_MISMATCH compares whitespace-normalized, case-insensitive names and skips null names.
- B10: Gap and summary text name the issuer ("The Eastside Community Food Pantry's May hours…") instead of the Appendix's "the food pantry's", because the Gaps rule says the message names the issuer. EVAL_BEFORE and SUMMARIES in mocks/jorge.py were updated to match. Gap messages are English only; summaries are en/es.
- B10: Unconfirmed_record gaps for months other than the best month come after the best-month gaps and before hours gaps, in month order. Summary: meets → path sentences + deadline; conditional → totals + "depends on" sentence; short → totals + "does not yet show" sentence. The deadline sentence only appears for meets (as in the Appendix).
- B10: LLM summary rewording uses `LlmClient.rephrase` (text-only prompt). The rewrite is accepted only if the multiset of numbers in it equals the template's; otherwise, or on any failure, the template is returned.
- B11: Packet and submission record PDFs are English-only (the summary paragraph keeps case_info.lang). The packet cover shows the best month's status as "Meets — the evidence appears to show…", "Conditional" or "Short", plus each unresolved rule id with its rules-file description. Deadlines get "(<status>)" whenever the rule is not confirmed. Evidence table "Verification" combines all fields: any ungrounded → Ungrounded; all grounded → Grounded; otherwise Not checked or Partly checked. "Source page" = hours page, else gross page, else issuer page. The submission record sorts entries by date. Both PDFs are built in memory and never written to disk.
- B12: eval_extraction.py counts a field correct when value and confidence both match ground truth; grounding rate = grounded / non-null extracted values; false passes = months the ledger on extracted records calls "meets" but the ledger on ground truth does not, summed over two scenarios (as extracted, and with every low-confidence field navigator-confirmed). Both ledgers use JORGE_CASE and validate_records first.
- F1: caseState keeps an always-present caseInfo (empty clientName, caseType renewal, lang en) so useT reads caseInfo.lang before setup; documents have status queued | uploading | done | error; exemptionAnswers are stored as ExemptionAnswer[] (one per id); a failed /api/health shows a "Cannot reach the server" badge.
- F3: Case setup edits caseInfo in shared state as the user types (so sample prefill shows directly); validation runs on "Continue". The response deadline preview is rfiReceivedDate + rules.thresholds.rfiResponseDays from GET /api/rules, labeled with rules.ruleStatuses.rfi_response_days when not confirmed; the authoritative deadline still comes from POST /api/evaluate.
- F4: The uploader pre-checks extension (pdf/png/jpg/jpeg) and 10 MB before sending (the backend still enforces MAX_UPLOAD_MB); rejected files are listed with an error and not sent. Sample documents upload automatically when step 2 opens in sample mode with no documents yet. "Continue to review" (enabled once no upload is pending and at least one is done) runs POST /api/validate on all records, then goes to step 3. The pipeline trace is a native <details>, opened by default when the document has warnings or a failed stage; known backend warnings are translated, others shown as sent.
- F5: Review edits commit on blur/Enter (selects on change); a navigator-edited value is sent as confirmed: true. Money fields are edited in dollars and stored as integer cents. Every change updates records locally, clears the stale evaluation, then re-runs POST /api/validate; only the newest response is applied. "Needs confirmation" = unconfirmed and (low confidence or ungrounded); the counter counts unconfirmed low-confidence fields. Exemption questions sit at the bottom of step 3, above "Evaluate".
- F6: Results show the backend summary as sent, the deadline with its rule status when not confirmed, month cards (counted hours = work + volunteer vs rules.thresholds.hours; income vs rules.thresholds.incomeCents; conditional months list each dependsOnUnresolved rule's rules.unresolvedRules description plus its id), gaps (backend messages, English only), and evaluation.possibleExemptions as "Possible exemption — navigator to confirm" with source link. Step 4 adds "Continue to packet" (step 5 is still a placeholder until F7).
- F7: PacketPanel shows the packet disclaimer on screen and enables "Download packet" only after an evaluation exists. The submission form defaults to today's date and channel "online"; "Documents included" is a checklist of successfully read file names (all checked by default); empty confirmation number/notes are sent as null. Entries can be removed; "Download submission record" is enabled once at least one entry exists. Submissions live only in case state.
- F8: On each step change the page scrolls to the top and focuses the case heading (tabIndex -1). The sample-load error is now dismissible like the other alerts. Fixed the EN/ES toggle, which marked both buttons as pressed (a shadowed `lang` variable).
- B13: Docker image mirrors the repo layout (/app/backend, /app/rules, /app/frontend/dist) so settings defaults work without env vars; node:22-slim builds the SPA, python:3.12-slim + `uv sync --frozen --no-dev` runs it; PORT defaults to 8000. Deploy target is Render via `render.yaml` (free plan, health check /api/health, autoDeploy off, no LLM env vars); the live URL is added to README.md after a manual deploy.
- S1.2: Frontend tests use vitest (`npm test` = `vitest --run`, node environment, picks up `src/**/*.test.ts` via the Vite config) with fast-check for property tests of the pure helpers in frontend/src/lib/.
- S2.1: New `POST /api/deadline` (body `DeadlineRequest{caseInfo}`, response `DeadlineResponse{deadline: Deadline | null, rulesVersion}`) wraps `reporting.deadline.response_deadline`, so the deadline chip can show the backend's date from Step 1 onward. The endpoint only adds a route; Evaluate is unchanged. It returns `deadline: null` when `rfiReceivedDate` is empty.
- S1.1: `packetReady` now holds the Packet-step heading ("{name}'s packet is ready to send"), as design.md specifies. The old download status message moved to a new key, `packetDownloaded`, and PacketPanel.tsx now uses it. `bestMonth` reads "Best month" / "Mejor mes" to match the Month_Strip label. The story copy holds no threshold numbers; numbers come in through {placeholders}.
- S2.3: The Step 1 deadline preview now comes from POST /api/deadline (stored as state.deadline; the browser `addDays` calculation is removed). CaseSetupForm re-requests it whenever case info changes and applies only the newest response; a failed request (for example, empty client name) keeps the previous value. After Evaluate, `evaluation.deadline` replaces it.
- S2.4: The DeadlineChip shows "{n} days left" only when 0 ≤ days from the reference date to the API deadline ≤ `rules.thresholds.rfiResponseDays` (whole calendar days, `lib/deadline.ts`); after the deadline it shows "The reply date has passed"; otherwise, or while rules are not loaded, the date only. The reference date is `caseInfo.rfiReceivedDate` for the sample case (`?sample=1`) so the demo shows a countdown, and the local date for every other case.
- S4.5: `state.priorEvaluation` holds the last non-null evaluation before the current one. SET_EVALUATION sets it to the outgoing evaluation when that is non-null and otherwise keeps it, so evaluate(conditional) → review edit clears to null → evaluate(meets) leaves priorEvaluation = conditional for the Results transition. RESET clears it.
- S5.3: The "live" Stage_Strip is honest. The backend runs all six stages in one POST /api/documents request, so while it is in flight every chip shows "Working" (CSS pulse, off under reduced motion) and when the result arrives each chip shows its real pipeline status. No per-stage progress is faked or timed.
- Headline and progress bars count work + volunteer hours, matching the ledger's meets path; training hours stay 'not counted yet' (job_training_approved unresolved).
- S7.1: Typeface is Inter (self-hosted via `@fontsource-variable/inter`, imported in main.tsx) with a system sans fallback in `--font-sans`.
- S7.1: Icons come from `lucide-react` only; every icon is `aria-hidden` and paired with a text label.
- S9.1: LineBox, TextLine, PageView live in backend/app/schemas/api.py next to DocumentResult; `DocumentResult.pages` defaults to [] so mocks, contract tests, and ground truth are unchanged until the pipeline fills it.
